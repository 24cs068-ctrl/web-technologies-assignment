1. Internet Overview

The Internet is a global network of networks — millions of computers, servers and devices connected together using a common set of rules (protocols) so they can exchange data. It doesn't belong to one company or country; it's a cooperative system that routes information from a source to a destination, usually in a fraction of a second.

The World Wide Web (WWW) is not the same thing as the Internet. The Internet is the physical and logical network; the Web is one service that runs on top of it — a collection of linked documents (webpages) accessed using HTTP/HTTPS. Email, file transfer (FTP) and video calls are other services that also use the Internet.

2. Fundamental Computer Network Concepts

A computer network is two or more devices connected so they can share data and resources. A few core ideas every website team should know:

  • Node — any device on the network (a laptop, a server, a phone).
  • IP Address — a numeric label (e.g. 192.168.1.10) that identifies a device on the network, similar to a postal address.
  • Protocol — an agreed set of rules for communication, e.g. HTTP, TCP/IP.
  • LAN / WAN — a Local Area Network covers a small area (one campus building); a Wide Area Network spans cities or countries (the Internet itself is the largest WAN).
  • Client–Server model — the client (browser) requests data; the server stores and returns it. This is the model the entire Web is built on.

3. URL and its Structure

A URL (Uniform Resource Locator) is the address typed into a browser to reach a specific resource on the Web. It has several distinct parts:

https://www.institution.edu/admissions/apply.html?year=2026
Scheme / Protocol — https
Subdomain — www
Domain name — institution
Top-level domain — .edu
Path — /admissions/apply.html
Query string — ?year=2026

4. Domain Name

A domain name is the human-readable name that stands in for a server's IP address (e.g. institution.edu instead of 203.0.113.42). The Domain Name System (DNS) is the internet's phone book — it translates the domain name a person types into the numeric IP address a computer needs.

5. Web Browsers and Web Servers

Web Browser

Software installed on the user's device (Chrome, Firefox, Edge) that sends requests for webpages and renders the HTML, CSS and JavaScript it receives into the page the visitor sees and interacts with.

Web Server

Software (and often the machine running it) that stores website files and listens for incoming requests, sending back the correct page, image, or data — e.g. Apache, Nginx, or a Node.js server.

6. Working Principle of a Website

Putting the pieces above together, here is what happens when a visitor opens the institution's homepage:

  1. The visitor types www.institution.edu into the browser.
  2. The browser asks a DNS server to resolve that domain to an IP address.
  3. The browser sends an HTTP request to the web server at that IP address.
  4. The web server locates the requested file (e.g. index.html) and sends it back in an HTTP response.
  5. The browser parses the HTML/CSS/JavaScript and renders the finished page on screen.

Conclusion

The Internet is the underlying network, and the Web is the linked-document service that runs on it. A URL identifies a resource by combining a protocol, domain and path, and DNS quietly translates that domain into an IP address for every request. Browsers and servers talk to each other using the client–server model — the browser asks, the server answers — and the page a visitor finally sees is the result of client-side code (JavaScript, for interactivity) working alongside server-side code (for data and logic). Understanding this chain is the first step before designing the institution's own site.
